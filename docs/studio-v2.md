# Image Studio：桌面工作室

本次重构新增独立 Go 领域内核、薄 Wails 绑定和 React 创作工作室。首页采用浅蓝玻璃、柔和曲线、双模式卡片及统一字体栈；作品、任务状态与统计来自真实本地数据，不填充虚构记录。

桌面主线统一维护 React + Wails + Go，独立 Gio 客户端已经下线，Go 后端和共享依赖保留。架构与旧深链关联注意事项见 [desktop-architecture.md](./desktop-architecture.md)。

## 启动

使用仓库 `go.work` 指定的 Go 工具链（当前最低 1.25.5，工具链 1.26.3），Node 22.18 或以上版本，以及 Wails v2。平台系统依赖仍见 [构建说明](./build.md)。

```bash
git fetch origin
git switch main
cd image-studio/frontend
npm ci
npm run build
cd ..
wails dev
```

前端预览可在 `image-studio/frontend` 运行 `npm run dev`。浏览器可以编辑、保存、导入和导出画布，数据保存在 IndexedDB；它不是在线 SaaS，不保存 API Key，不代理收费生成请求。

工作室是唯一创作入口，已移除「经典编辑」按钮及路由。Android APK 已下线。旧上游与可读取的历史在工作室启动时迁移，不删除原文件。任务由桌面进程管理；旧数据兼容接口仍保留，避免破坏升级。

## 连接上游与生成视频

打开「设置 → 添加上游」，填写名称、Base URL、协议、API Key、图像模型 ID、视频模型 ID。模型名由用户明确填写，视频模型不会被替换成图像模型。测试连接仅读取 `/models`，不会触发生成；模型列表可见不证明生图权限或扩展参数可用。接口选择旁提供 TIPS；sub2api 用户见 [接入指南](./sub2api.md)。

Base URL 按填写的原样判断：以版本段结尾的地址（如 `…/v1`、`…/api/v3`、`…/openai/v1`）或以 `/openai` 结尾的地址（如 `…/v1beta/openai`）直接拼接端点；其他地址（如 `https://relay.example.com`）补上 `/v1`。测试连接、视频查询和图像请求因此落在同一个 API 根下。填写带反向代理子路径的完整 API 根路径时，以设置中的端点预览为准。

### 统一配置与旧数据迁移

桌面端只有一份上游配置，保存在 `studio.json`，密钥保存在系统凭据库。首次启动新版本时，经典编辑原先保存在浏览器存储中的上游会连同密钥一起导入；导入可重复执行，已删除的上游不会被再次导入。浏览器中的旧列表只作为迁移来源，不再作为独立编辑器入口。

导入不会丢弃配置：超出共享规则的模型列表会被截短（最多 5000 项，单项最长 256 字节）；地址不符合共享规则的上游（例如未开启不安全连接的远程 HTTP）以无地址的草稿导入，补填地址时需要重新输入密钥。原有凭据项暂时保留，之后在共享配置中更换、清除或删除密钥时随之删除。迁移失败时保留旧记录和原文件，排查路径或存储问题后可重试。

旧代理设置会导入工作室，可在设置中修改；代理模式包括系统代理、不使用、自定义，默认跟随系统代理。直连时解析并校验目标地址。经过代理时，本机先解析主机名：解析到私网、链路本地或元数据地址即拒绝；本机无法解析、或只得到代理工具的 Fake-IP 时，只放行公网形式的域名和用户配置的上游主机，`.lan`、`.local`、`.internal` 等内网后缀和单标签主机名一律拒绝。代理会再次解析域名，因此无法完全排除 DNS 重绑定。

OpenAI 兼容图像任务复用 `go-cli/pkg/client`，支持流式 Images API（`stream` 与 `partial_images`）和 Responses 图像工具（需填写文本模型 ID）。SSE 可以减少空闲超时风险，不能保证所有网关都不会返回 524。工作室只提交一次生成请求，不自动重发结果未知的任务。模型与路径能力、提示词模式见 [使用说明](./usage.md)。

| 适配器 | 创建视频 | 查询任务 | 获取文件 |
|---|---|---|---|
| xAI | `POST /videos/generations`，JSON | `GET /videos/{request_id}` | `video.url` |
| OpenAI 兼容 | `POST /videos`，multipart | `GET /videos/{id}` | URL/base64，或鉴权的 `/videos/{id}/content` |

xAI 请求使用 `duration`、`aspect_ratio`、`resolution` 和可选 `image.url`；OpenAI 兼容请求使用 `seconds`、`size`、可选 `input_reference` 文件。空时长省略，由上游决定。当前适配器支持 xAI 1–15 秒、OpenAI 兼容 4/8/12 秒；实际可用模型与参数仍以上游权限和文档为准。

协议依据：[xAI 视频生成文档](https://docs.x.ai/developers/model-capabilities/video/generation)、[OpenAI 视频创建文档](https://developers.openai.com/api/reference/resources/videos/methods/create)。兼容网关不一定实现相同字段，不承诺所有供应商通用；其他供应商应增加单独的 `Runner` 实现。

简洁模式可直接提交图片或视频任务。专业模式可以连接：

```text
提示词 → 图像生成 → 视频生成
```

每个生成节点最多一张参考图片，支持图片生成结果作为下游参考，不接受视频充当图片。整个工作流在同一事务内校验并创建任务；任一节点无效时整批拒绝，不先提交部分收费请求。运行前提示生成节点数和可能产生的 API 费用。

## 分层结构

```text
image-studio/backend/studio/

  repository.go   版本化本地仓储、写入与损坏保护
  store.go        不可变已发布状态、事务、变更日志与增量同步
  profiles.go     上游元数据、版本化安全凭据引用
  engine.go       有界提交名额、幂等任务、依赖调度、暂停恢复
  provider.go     明确协议的请求、轮询与受限媒体下载
  openai_images.go 通过 go-cli 的流式图像请求，单次发送与结果分类
  network.go      代理选择、直连地址校验与超时
  assets.go       素材落盘、结果回填、Range 媒体服务
  studio_test.go  领域测试与本地 mock 上游测试
image-studio/backend/studio_v2.go
  Wails 生命周期、系统凭据适配、原生保存对话框
image-studio/frontend/src/studio/
  StudioApp.tsx   首页、简洁创作、作品、工作流、历史、设置
  Canvas.tsx      世界坐标画布、节点、连线、撤销与重做
  useStudio.ts    草稿、自动保存、冲突合并与事件驱动的增量同步
  sync.mjs       增量快照合并与任务进度
  graph.mjs      几何、拓扑、三方合并、模板白名单
  client.ts      桌面绑定与本地浏览器预览
  studio.css     统一字体、浅蓝玻璃主题、响应式布局
```

这是桌面主创作链路的重构，不是新增公网多用户服务。没有 Redis 集群、在线账号系统或多人协作服务；保留的旧后端接口用于历史迁移、文件操作和共享兼容能力，不代表保留经典界面。

## 任务与收费安全

任务先保存再发请求，默认两个 worker。同一任务 ID、相同内容返回已存在任务；同 ID 不同内容拒绝。成功提交后再次点击生成会创建新任务，可能产生新费用。

请求在与上游建立连接之前失败（DNS、连接、TLS 证书、代理、受限地址）时直接标记失败，错误以「请求未发出」开头，可以放心重新生成。连接建立后出现超时、5xx 或结果无法确认时标记 `uncertain`，不自动重发可能已被计费的 POST；流式响应只返回了预览帧就结束，同样按结果未知处理。上游明确给出答复（4xx、错误事件、或已完成但没有图片）时标记失败并说明原因。已保存远端 ID 的视频任务中断后可恢复 GET 查询；查询 429/5xx 使用退避。已提交的任务在恢复时遇到本地问题（系统凭据库暂时不可读、代理设置无效）会重新暂停，而不是失败，问题解决后可以再次恢复。

图片接口返回结果链接后，链接先落盘再下载。下载失败时任务暂停，恢复后只重新下载，不重新生成，也不再读取密钥和参考图；链接已失效（4xx）时任务标记失败，需要时再手动重新生成。base64 和下载结果直接流式写入媒体目录的临时文件，不整块驻留内存。

worker 数只限制同时进行的提交：上游接受任务（返回远端 ID 或结果链接）后立即释放名额，长时间的视频轮询和下载不会阻塞后续提交。重新打开应用不会自动执行积压收费任务：排队任务暂停，提交结果未知的任务需先到上游核对。

取消只保证停止本地任务或轮询，不保证远端取消或退费。依赖失败会阻止下游任务发出请求。生成结果固定回填提交时的画布，不跟随用户后来切换的项目。

## 状态与同步

内核把已提交的数据发布为不可变状态：写操作串行执行，先原子写入 `studio.json` 再发布；读取快照、增量和媒体请求都不加锁，不会被磁盘写入或系统凭据操作阻塞。

每次落盘的修改都有递增的 revision。`GetChanges(epoch, revision)` 只返回该 revision 之后变化的实体和被删除的 ID；应用重启后 epoch 改变，或客户端落后超过变更日志窗口时，返回完整快照。每次落盘后发送 `studio:changed` 事件；任务进度只保存在内存，通过 `studio:progress` 事件推送，不为进度写盘，任务结束时随最终状态一起保存。

界面收到 `studio:changed` 后按 revision 拉取增量，进度事件直接更新对应任务，不发请求；桌面端只保留 30 秒一次的兜底刷新，浏览器预览没有事件，仍每 2.5 秒读取本地快照。未变化的集合保持引用不变，作品搜索与统计只在数据变化时重算；作品、素材与任务历史每次显示 60 项，可继续展开。

## 密钥、存储与隐私

数据目录：`os.UserConfigDir()/ImageStudio/studio-v2/`。`studio.json` 保存元数据和任务，`media/` 保存下载的作品。旧数据目录不变。

API Key 存入操作系统凭据库，不写入 JSON、浏览器存储或工作流导出文件。每次更新密钥先创建独立槽，再提交引用；数据库写入失败不会改变旧地址对应的密钥。未结束任务固定使用提交时的上游配置和密钥版本。改变 Base URL 时必须重新输入密钥。凭据库不可用时明确报错，不回退到明文保存。

媒体只通过注册过的本地素材 ID 访问，支持 Range 请求。下载检查真实 MIME 和文件大小，拒绝 SVG/HTML；不会把 Bearer Token 发给外部 CDN。直连时检查解析后的目标 IP，拒绝私网、链路本地、元数据地址；显式开启本地服务后仅允许回环地址。代理工具的 Fake-IP 网段（198.18.0.0/15）不再被拒绝。单个上游可以显式允许不安全连接（远程 HTTP、跳过证书校验），此时密钥可能被截获。

提示词、项目元数据和媒体文件本身并非整体加密，依靠本机账户与磁盘权限保护。模板包含用户写的提示词；即使不导出凭据字段，仍需检查文本是否粘贴了敏感信息。生成时选定的提示词和参考图会发送到用户配置的上游。

## 画布与保存

支持平移、指针锚定缩放、节点拖动、Shift 多选、Delete 删除、连线、适配全部、Ctrl/⌘+Z 撤销和重做。提示词、生成器、便签、图片和视频素材可以在同一画布工作。

视口、节点和连线按项目保存。拖动、平移和滚轮缩放先在画布内绘制，松手（滚轮停止 250 毫秒）后才写入项目，一次手势只产生一次保存和一步撤销；未移动的节点不会重新渲染。自动保存采用 revision 乐观并发检查；三方合并保留后台新增结果与本地编辑，同字段冲突明确提示，不静默覆盖草稿。冲突时可先导出草稿，再重新载入。模板只包含节点、连线、参数和文本，不携带媒体文件或素材绑定；导入后重新选择素材。

撤销最多 50 步，仅在当前编辑会话有效，刷新不保留撤销栈。没有视频剪辑、转码或时间线功能，也未声称超大画布虚拟化或多人实时协作。

## 容量与验证

内核默认 2 个 worker，可配置 1–8；最多 128 个未结束任务、10000 条任务历史、1000 个画布。单画布最多 2000 节点与 4000 连线，缩放 10%–400%。导入及参考图片最大 20 MB，输出媒体最大 160 MB，本地 JSON 最大 64 MB。存储面向单桌面进程，不支持多个进程同时修改同一数据库。

```bash
cd image-studio
go test -race -count=3 ./backend/studio/...
go test -race ./backend/
cd frontend
npm ci
npm test
npx tsc --noEmit
npm run build

# 可选的生产构建浏览器验证，无真实 API Key
npm install --no-save --package-lock=false playwright@1.55.1
npx playwright install chromium
node scripts/studio-browser-smoke.mjs
```

旧 Node 22 版本运行直接导入 TypeScript 的测试时可能需要 `NODE_OPTIONS=--experimental-strip-types`。CI 使用更新的 Node 22。

`.github/workflows/studio-rebuild.yml` 包含 gofmt、go vet 与 staticcheck 检查、go-cli 与 Linux race、Windows 原生核心、Studio 源码的 Prettier 检查、完整前端测试与类型检查、生产构建、Windows 交叉编译，以及 Chromium 画布交互与增量同步回归。`studio-browser-evidence` 保留对应提交的日志、截图和报告；是否通过以该提交的实际 Actions 结果为准。

自动测试只使用本地 mock 上游，没有提交真实收费请求。发布前仍需在目标桌面系统人工验证系统凭据库、保存对话框、退出恢复、WebView 视频播放以及有权限的真实图像/视频 API。CI 成功不等于所有平台 GUI 与所有第三方上游均已验收。
