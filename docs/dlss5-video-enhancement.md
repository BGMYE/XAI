# 生成视频中的 DLSS5 增强

DLSS5 视频增强位于新版工作室的「生成视频」表单中。开启开关后展开画面参数、预览和导出设置；不增加独立创作入口。

## 使用流程

1. 在生成视频表单中开启「DLSS5 视频增强」。
2. XAI 自动检查随应用提供的视频引擎和当前显卡。用户不需要安装 Python、DLSS5Tool，也不需要选择运行库文件或填写路径。
3. 选择 XAI 的画面预设，调整增强强度和原片混合；需要时展开高级参数，调整色调、结构、皮肤细节和已检测可用的时间一致性选项。
4. 分别选择预览和导出分辨率，然后生成视频。上游生成完成后，原视频先保存，再执行本地增强。
5. 在同一表单选择已生成的视频，指定短片时间段进行对比预览。修改参数后可「应用参数并导出」，直接处理原视频，不再次调用上游生成接口。

本地引擎不可用时，开启增强的生成请求会在上游提交之前被拒绝。关闭开关后，普通视频生成保持原有行为。

## 分辨率

- 预览和导出分别保存，可以选择源尺寸或自定义宽高。
- 自定义宽高必须为偶数，至少 128 像素。
- 预览每边最多 4096 像素，总像素不超过 3840 × 2160；片段最长 10 秒。
- 导出每边最多 8192 像素，总像素不超过 7680 × 4320。实际可处理尺寸还取决于显存和编码器。
- 不同比例使用等比缩放和补边，避免拉伸人物。自定义缩放不是 RTX Video 超分功能。
- 预览分辨率不会改变成片分辨率。预览中的原片与增强片采用相同片段和画幅。

## Windows 开箱使用

完整的 Windows x64 安装包负责安装应用及其私有视频引擎。便携版需要完整解压，然后双击 `image-studio.exe`；引擎保存在同目录的 `runtimes/dlss5` 中。不应单独复制 EXE 或混用不同发行包的引擎文件。

Python 解释器和第三方 Python 依赖被封装在 XAI 的后台引擎中，不使用用户机器的 Python、PATH 或上一版保存的开发工具路径。运行时也不会要求用户执行 pip 或打开 DLSS5Tool 的界面。

开启增强后自动检测；用户可在引擎状态卡中重新检测。只有实际 GPU 初始化通过后，才允许提交带增强的视频生成请求。缺失或不兼容的引擎显示完整安装包的修复提示；不向用户暴露 Python、DLL 路径等部署选项。兼容的 NVIDIA GPU 和驱动仍是运行条件，打包无法替代硬件能力。

应用按版本清单校验引擎文件的相对路径、架构和 SHA256，防止混装或损坏。校验值用于完整性检测，不代替发布者签名或分发授权。完整引擎由发行者随包提供，不在用户运行时从社区链接自动下载 DLL。

## 开发与发行

XAI 复用固定版本 DLSS5Tool 的 MIT 处理核心，通过独立后台进程执行真实的 DLSS Neural Rendering。工作室自行管理参数、预览、任务、进度、取消、素材与导出，不复用上游桌面界面。

构建脚本位于 `image-studio/scripts/dlss5/`，只供开发者和发布流水线使用。Windows 构建阶段封装 Python 与媒体依赖，并将发布者提供的原生宿主、FFmpeg、获授权 NVIDIA 运行库及相应许可文件组成应用私有引擎包。Windows x64 发行必须携带经过校验的完整引擎；缺失时停止打包，不能把单独的 Go EXE 宣称为开箱可用的增强版。

仓库本身不含 NVIDIA 运行库或模型权重，也不能从上游源码推导出这些二进制的再分发授权。要产出实际可用安装包，发布者仍需提供可以随 XAI 分发的原生运行资产，并在 Windows 目标机器上构建和验收。终端用户无需承担这些构建步骤。

首版提供 SDR 神经渲染，输出浏览器兼容的 H.264 MP4。HDR 输入会明确拒绝，不会静默转为 SDR。本轮不提供 RTX Video 超分、插帧或实验强度扩展。

## 任务与预览

增强使用独立的本地任务状态，不占用上游生成协议，也不向本地处理进程传递 API Key。原片始终保留，增强结果作为新的素材入库。

每次完整导出固定当前参数。修改表单或制作新预览不会改变已经运行的导出；「仅重试增强」使用失败任务的参数，「应用参数并导出」使用当前表单参数。失败或取消不触发付费生成重试。

短片预览需要先完成该片段的实际处理，再播放和比较。可开启「停止调参后自动更新短片」，停止调整 1 秒后处理最新参数；默认关闭，取消预览时也停止自动更新。它不保证神经渲染达到视频原帧率，也不将缓存播放速度标为推理速度。切换素材或参数后，过期预览不会回填为最新结果。

增强和预览共享本地 GPU 调度，避免同时启动多个大任务耗尽显存。取消及关闭应用会终止处理进程与其派生进程。中断的完整视频任务需要重新处理，不承诺帧级断点续传。

## 来源与验证边界

核心参考：[banbanzhige/DLSS5Tool](https://github.com/banbanzhige/DLSS5Tool)，固定源码版本 `e23654c6b6743ebf7487256c10f93455c8ba4bfd`。自有源码的 MIT 许可证及来源记录随桥接模块保留；NVIDIA 运行库、FFmpeg 和其他依赖仍受各自条款约束。

开发环境可验证参数、分辨率、任务状态、取消、进程协议、原视频保留和界面操作。实际 GPU 兼容性、吞吐、画质和连续运动效果必须在目标 Windows/RTX 设备上验证；通过构建或替身处理器测试不代表完成 GPU 实测。

上一轮使用真实 FFmpeg/PyAV 和明确的 NR 恒等替身，验证了固定/可变帧率的导出与短片预览、时码一致和原音轨保留；这部分不验证 GPU 增强画质。

目标发行包首次验收时，应在未安装 Python 或 DLSS5Tool 的干净 Windows 设备上完整安装，直接启动 XAI，确认自动引擎检测、短片前后画面、音画同步、显存占用和取消行为，再执行完整导出。交叉编译的单个 EXE 和源码 ZIP 不是这项开箱验收的替代品。

当前源码验证：前端 367 项测试、类型检查和生产构建通过；DLSS5 与 Studio 后端竞态检测通过；桥接 28 项、引擎封装 29 项测试通过；Windows x64 主程序交叉构建通过。900 × 640 和 1440 × 900 的界面检查确认了无路径配置、预设不改尺寸、参数重启恢复和单一入口。发布工作流及安装器回退做了静态检查，尚未执行 Windows 冻结引擎构建、安装器运行或真实 GPU 验收。
