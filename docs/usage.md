# 工作室使用与上游配置

新版工作室是唯一创作入口，设置和侧栏不再提供「经典编辑」。桌面支持 Windows、macOS、Linux；Android APK 已下线。浏览器仅提供本地画布预览，不保存 API Key、不代理生图。

## 首次配置

1. 打开「设置 → 添加上游」，填写名称、Base URL 和 API Key。
2. 按服务商文档选择接口协议；使用 sub2api 时选择其预设，底层仍为 OpenAI 兼容协议。
3. 填写账号实际可用的精确图像模型 ID。Responses 另需填写能调用图像工具的文本模型 ID；视频模型独立配置。
4. 保存后可测试连接。测试仅读取模型列表，不提交收费生成；模型出现在列表中不证明该 Key 有生图、编辑或工具权限。
5. 阅读接口旁的 TIPS，按实际验证结果设置能力。未知能力保持「未确认」，不要凭模型名称推断。

Base URL 填写真实 API 根路径，例如 `https://gateway.example/v1` 或 `https://gateway.example/proxy/v1`。端点预览帮助检查实际调用地址。修改地址后需要重新输入密钥。

## 协议怎么选

| 设置 | 适用场景 | 需要确认 |
|---|---|---|
| xAI 协议 | 上游提供 xAI 原生图片或视频接口 | 按比例设置图片；视频字段为 `duration`、`resolution` |
| OpenAI 兼容协议 | OpenAI 接口或 sub2api 等兼容网关 | 上游实际实现对应端点；同名模型不代表协议相同 |
| Images API | 直接文生图、参考图编辑、已验证的蒙版编辑 | `/images/generations`、`/images/edits`，及模型支持的尺寸、质量、格式 |
| Responses API | 需要文本模型理解和图像工具编排 | `/responses`、文本模型权限、显式 `image_generation` 工具权限 |
| HTTP SSE | Responses 的起步传输方式 | 代理不缓冲事件、网关支持流式响应 |
| WebSocket | 上游已完成实际生成和编辑验证 | Upgrade、鉴权、连接中断行为；不是画质档位 |

**Images 也支持 SSE。** 是否流式由上游能力与兼容配置决定，不能把 Images 等同于非流式。SSE 有助于减少空闲连接超时，但无法保证消除 524/504。切换协议或传输会创建另一次请求，已有任务结果不明时应先核对上游。

sub2api 的桥接策略、推荐配置和实测清单见 [sub2api 接入](./sub2api.md)。

## 能力和参数

能力记录按精确模型 ID 和 Images / Responses 路径区分，可以确认生成、编辑、流式、蒙版、参考图上限以及允许的质量、尺寸和格式。省略的能力表示未知；客户端的字段过滤和校验不能代替上游测试。

更改 Base URL、密钥、模型、协议、图像接口、传输、请求策略、安全连接选项或提供商预设后，旧能力确认失效，需重新核对。`GET /models` 只用于发现模型，不自动填写“支持”。

- 优先使用「OpenAI 标准」策略；只有服务商明确支持时才启用中转扩展字段。
- 不因 `gpt-image-2*` 名称较新而自动切换模型。其 `input_fidelity` 不应被统一强制为 `high`。
- `high`、透明背景、大尺寸等只在对应模型和路径支持时使用。PNG 保存避免额外有损压缩，不会提高模型固有画质。
- 模型原生分辨率与本地插值放大后的像素尺寸不同；旧版 CPU 放大实现不代表 GPT 输出了更高原生分辨率。

「高质量成品预设」只在能力记录确认 `high`、PNG 和至少一个明确尺寸后可用；它选用记录中像素面积最大的原生尺寸，不替换模型。输入保真选项仅在当前模型和路径确认支持并列出档位后显示。

## 提示词模式

Responses 可以选择「精确执行」或「创作辅助」。前者要求原样传递，适合固定中文文字、品牌要求和精确编辑；后者允许补充视觉表达，同时保留主体、文字、数量和编辑限制。两者都强制调用图片工具，避免只返回文字。

两条图像路径都可先用「优化并确认提示词」：主动发起可能收费的文本优化，检查和编辑建议后确认，再单独生成。参考图和蒙版不发送给文本模型；Images 生图也需另外配置支持 Responses 的文本模型才能优化。

Images 直接发送提示词，不能通过客户端的 Responses 指令控制网关内部如何转换请求。详细边界见 [提示词模式](./no-prompt-revision/README.md)。

## 创作与继续编辑

在简洁创作中选择图片或视频、上游和结果画布，输入描述后明确点击生成。专业模式可创建提示词、生成、素材和便签节点，连接工作流并保存项目；运行前检查生成节点数及可能的 API 费用。

作品可以用作下一轮参考图。此方式把完整成品和新指令提交给上游，不依赖 `previous_response_id` 或服务器保存对话。

OpenAI 图像创作中的「更多参考图与蒙版」可按顺序追加参考图，首张为主图。蒙版选择器在确认该模型和路径支持后开放：选择已导入的 PNG，尺寸必须与首张参考图一致，并包含透明编辑区域。这里选择已有蒙版，不提供旧版蒙版画笔；输入使用原始素材。

接收到的最终图片独立入库；预览帧不算最终成品。没有最终图片时不能把任务当作完整成功。多张结果、请求 ID 和用量仅按上游实际返回记录；未返回的计费信息不能由客户端推算。

## 代理与网页导入

工作室设置可选择系统代理、不使用代理或自定义 HTTP(S) 代理，旧版设置会迁移。修改后作用于后续请求，已运行任务保持原连接。

`image-studio://` 链接到达桌面后，工作室先展示导入确认；确认只填入创作草稿，不自动生图。操作系统的协议关联仍需指向当前 Wails 应用，详见 [网页导入说明](./prompt-import.md)。

## 历史与任务状态

工作室元数据保存在系统配置目录的 `ImageStudio/studio-v2/studio.json`，图片和视频在相邻 `media/` 目录。API Key 独立保存在系统凭据库。旧上游与可读取的旧历史在启动时迁移，失败条目保留来源文件和本地记录，不要求再打开经典编辑器。

工作室一次生成只提交一次请求。连接建立后的超时、5xx 或断流可能已经执行并计费，任务会保留不确定状态，不自动重发或切换账号、协议。取消只停止本地处理，不保证上游取消或退款。已保存链接的下载恢复不重新生成。

旧目录批处理、Konva 标注、旧快捷键等历史文档不代表新版界面提供相同入口；当前入口以 [工作室说明](./studio-v2.md) 为准。

可选 Worker 和共享远程内核也只提交一次图片任务，不自动切上游或改写尺寸重发；Worker 透传流和可用 request ID。可确认尚未提交的 WebSocket 握手兼容回退不等于重新生成，细节见 [Worker 说明](../cloudflare-worker/README.md)。
